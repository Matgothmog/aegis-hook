# 10-day plan

Solo build. The rule for every day: **the demo must stay runnable.** Never end a day
with a broken `forge test`.

## Day 1–2 — foundations ✅
- [x] Repo, Foundry, v4-core + v4-periphery wired
- [x] Own `BaseHook` — v4-periphery removed theirs, so Aegis carries an auditable one in-repo
- [x] `AegisHook` with permissions declared and asserted against the address bits
- [x] Test fixture: PoolManager + two pools (vanilla / Aegis) side by side
- [x] Swap routes through the hook — 16 tests green

**Gate:** ✅ a swap executes through AegisHook on a local pool.

## Day 3–4 — core mechanism ✅ (pulled forward)
- [x] MEV tax in `beforeSwap`, `OVERRIDE_FEE_FLAG` returned correctly
- [x] Reject static-fee init in `beforeInitialize` — fail closed rather than silently inert
- [x] Per-block tick checkpoint + deviation breaker
- [x] Volume rate limit; guardian halt latch
- [x] Guardian role with hard-coded bounds it cannot escape, and withdrawals never blocked
- [x] Fuzzed the fee curve for bounds and monotonicity

**Gate:** ✅ breaker rejects an oversized intra-block move and re-anchors each block.

### Remaining refinements
- [x] ~~Position key collides across users of one router~~ — checked against v4-core:
      `Position.calculatePositionKey` uses the same `(owner, tickLower, tickUpper, salt)` tuple,
      where owner is likewise the router. The hook's position identity *is* the protocol's, and
      uniqueness comes from `salt` (PositionManager uses the NFT id). Not a defect; documented
      in the contract so the constraint on routers is explicit.
- [ ] Volume ceiling is denominated in token0 only; decide whether that is the right unit.
- [ ] Chainlink feed as an external reference, to catch manipulation walked across blocks —
      the current breaker only sees within-block movement.

## Day 5–6 — attack lab (the differentiator)
- [x] `SandwichTest` — frontrun / victim / backrun, measured PnL, vanilla vs Aegis
      (vanilla +0.0690 token0, Aegis -0.2308 token0)
- [x] `JitLiquidityTest` — supply before, withdraw after; vanilla bot takes +0.015184 token0
      (essentially the whole fee), Aegis reverts the withdrawal
- [x] `OracleManipulationTest` — single-block price push; vanilla moves -6713 ticks (-48.9%),
      Aegis bounded at 500 ticks (-4.9%), unbuyable at 500 gwei, unsplittable within the block
- [x] Proved the breaker bounds velocity and not direction: -20.2% still reachable over 6 blocks
- [x] Each attack runs twice: vanilla vs Aegis
- [ ] ~~`DonationGriefer`~~ — **dropped, with reason.** `donate` adds to fee growth for in-range
      liquidity without touching the price, so it is not a price-manipulation vector and Aegis
      does not hook it. Writing a test that "passes" here would demonstrate nothing; saying so is
      better than padding the lab.
- [ ] Benchmark table emitted as markdown, regenerated by CI

**Gate:** the benchmark table shows attacker profit going negative. This is the
slide the submission is built around — if it lands nowhere else, it lands here.

## Day 7 — ship it onchain (mostly done early)
- [x] `AegisDeploy` library — CREATE2 salt mining, shared by the script *and* the tests, so the
      tested path is the deployed path
- [x] `DeployAegis.s.sol` with verified PoolManager addresses per chain
- [x] `test/Deploy.t.sol` — closes the gap where every other test used `deployCodeTo` (which
      etches bytecode and skips address derivation entirely, the part most likely to fail)
- [x] `test/fork/UnichainSepolia.t.sol` — against the **real** deployed v4 on chain 1301:
      live manager accepts our mined hook, honours the `beforeSwap` fee override, and an
      `afterSwap` revert genuinely unwinds
- [x] Dry run clean: salt `0x374c`, permission bits `10944` = `0x2AC0`
- [ ] Broadcast for real (needs a funded key — see DEPLOYING.md)
- [ ] Seed pools + liquidity, run live swaps against the deployed hook
- [ ] Verify contracts on the explorer
- [ ] Secondary deploy: Arc testnet
- [ ] Subgraph: index `MevTaxApplied`, `SwapRejected`, `BlockCheckpointed`

**Gate:** a real transaction on a public testnet shows a tax charged.

## Day 8 — watchtower
- [ ] MCP server over the subgraph: `getPoolThreatLevel`, `getRecentAttacks`,
      `getTaxCollected`
- [ ] Agent answers "is this pool under attack right now?" from live data
- [ ] Chainlink feed wired as the breaker's external reference

**Gate:** ask the agent a question, get an answer grounded in chain state.

## Day 9 — one page, no more
- [ ] Single dashboard: pool state, breaker status, tax collected, recent blocks
- [ ] Live swap button, and a "run the attack" button that visibly fails

**Hard scope limit.** One page. No auth, no routing, no design system. If Day 9 runs
long, the dashboard gets cut before anything else — the Foundry benchmark is the
real proof and it already exists by Day 6.

## Day 10 — submission

## Risk register

| Risk | Mitigation |
|---|---|
| Hook address mining is fiddly and eats a day | Do it Day 1, not Day 7 |
| v4 periphery API drift vs. tutorials | Pin dependency commits; read `lib/` source, not blog posts |
| MEV tax needs priority ordering to be honest | Target Unichain; state the assumption plainly rather than overclaiming |
| Attack lab is where the value is but sits mid-schedule | If behind by Day 5, cut the dashboard and Arc deploy, never the lab |
| Solo dev, 10 days, no slack | Every gate above is a checkpoint to cut scope at, not a deadline to slip |

## Explicitly out of scope

Written down so they don't creep in later: no cross-chain, no custom router, no
governance, no token, no mainnet deploy, no audit-grade formal verification (the
fuzz suite is the honest ceiling for 10 days).
